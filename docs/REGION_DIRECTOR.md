# Региональный директор Dust and Dead

Директор — это сервер-агрегатор, к которому клиент подключается **первым**. Он
не проводит матчи и не хранит их состояние: он лишь возвращает список
матчмейкинг-серверов по регионам, после чего клиент сам замеряет задержку до них
и подключается к самому быстрому.

Отдельный игровой сервер описан в [ONLINE_SERVER.md](ONLINE_SERVER.md); директор
разворачивается независимо и, как правило, на отдельной небольшой машине.

## Как проходит подключение

1. Клиент запрашивает `GET /v1/regions?code=<код поиска>`.
2. Директор отдаёт список регионов: адрес `wss://`, здоровье, загрузку и —
   если код поиска уже занят конкретным регионом — поле `pinnedRegionId`.
3. Если регион закреплён за кодом, клиент идёт туда без замеров: смысл кода в
   том, чтобы двое друзей попали в одну комнату, а не в ближайшую.
4. Иначе клиент открывает пробные WebSocket-соединения к нескольким регионам
   (по умолчанию к четырём), дожидается `server.hello` и меряет прикладной
   round-trip через `session.ping` / `session.pong`.
5. Побеждает регион с наименьшей медианой пинга; загрузка добавляет небольшой
   штраф, чтобы игроки не собирались все на одном сервере.
6. **Выигравшее пробное соединение становится боевым** — второго рукопожатия
   нет. Проигравшие сокеты сразу закрываются.
7. Для кода поиска клиент отправляет `POST /v1/route/claim`, чтобы следующий
   друг с тем же кодом попал в тот же регион.

Переподключение всегда возвращается в уже выбранный регион: сессия живёт именно
там, поэтому гонка замеров при реконнекте не повторяется.

## Откуда директор знает о регионах

Регионы сами присылают heartbeat — директор их не опрашивает. Это работает, даже
если регион стоит за NAT, и даёт директору настоящие цифры загрузки.

Каждый игровой сервер с заполненными `DIRECTOR_URL`, `DIRECTOR_TOKEN`,
`REGION_ID` и `REGION_PUBLIC_URL` раз в `REGION_HEARTBEAT_INTERVAL_MS`
отправляет `POST /v1/regions/heartbeat` с версией протокола, готовностью,
числом матчей и соединений и списком открытых комнат с кодами поиска.

- Регион с чужой версией протокола отвергается целиком: иначе директор раздавал
  бы игрокам сервер, с которым их сборка не может разговаривать.
- Регион перестаёт быть маршрутизируемым через `REGION_TTL_MS` после последнего
  heartbeat, но остаётся в списке — клиент в процессе переподключения ещё должен
  уметь найти его адрес.
- Заполненный и переполненный регион (`activeMatches >= maxMatches`) виден, но не
  предлагается новым игрокам.
- `REGIONS` позволяет объявить регионы статически. Такая запись показывается, но
  считается непроверенной (`verified: false`) и не маршрутизируется, пока регион
  реально не отчитается.

Список открытых кодов из heartbeat — источник истины для закрепления кода за
регионом. Клиентский `claim` лишь закрывает промежуток до следующего heartbeat и
живёт `ROUTE_CLAIM_TTL_MS`.

## HTTP-интерфейс

| Метод и путь | Назначение |
| --- | --- |
| `GET /v1/regions[?code=]` | Список регионов и закрепление кода. Публичный, CORS `*`. |
| `POST /v1/route/claim` | Закрепить код за регионом. Побеждает первый; ответ всегда содержит победителя. |
| `POST /v1/regions/heartbeat` | Регистрация региона. Требует `Authorization: Bearer <DIRECTOR_TOKEN>`. |
| `GET /healthz` | Живость процесса. Используется контейнерным healthcheck и Caddy. |
| `GET /readyz` | `200` только когда хотя бы один регион готов принимать игроков. |
| `GET /metrics` | Диагностика. Caddy отдаёт по нему `404` наружу. |

`/readyz` намеренно строже `/healthz`: свежеподнятый директор жив, но пока
никого не может направить, и в балансировщик его пускать рано.

## Развёртывание директора

Домен директора должен резолвиться в эту машину, порты `80/tcp`, `443/tcp` и —
для HTTP/3 — `443/udp` открыты.

```bash
cp .env.example .env
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Полученное значение впишите в `.env` как `DIRECTOR_TOKEN` и укажите адрес:

```dotenv
DIRECTOR_SITE_ADDRESS=play-director.example.com
DIRECTOR_TOKEN=replace-with-generated-64-hex-character-value
```

Запуск:

```bash
docker compose --env-file .env -f deploy/compose.director.yml config --quiet
docker compose --env-file .env -f deploy/compose.director.yml build --pull
docker compose --env-file .env -f deploy/compose.director.yml up -d
```

Проверка снаружи:

```bash
curl --fail --show-error https://play-director.example.com/healthz
curl --show-error https://play-director.example.com/v1/regions
```

Пока не зарегистрировался ни один регион, `/v1/regions` вернёт пустой список, а
`/readyz` — `503`. Это ожидаемо.

## Подключение региона к директору

В `.env` каждого игрового сервера добавьте его личность и **тот же** токен:

```dotenv
REGION_ID=eu-central
REGION_LABEL=Europe (Frankfurt)
REGION_PUBLIC_URL=wss://eu.play.example.com/online
DIRECTOR_URL=https://play-director.example.com
DIRECTOR_TOKEN=the-same-value-as-on-the-director
```

`REGION_PUBLIC_URL` — адрес, по которому игрок реально достучится до региона, а
не внутренний порт контейнера. `REGION_ID` должен быть уникален в пределах
флота: одинаковый id считается одним и тем же регионом, и последний heartbeat
перезапишет предыдущий.

После `docker compose ... up -d` регион появится в `/v1/regions` в течение одного
интервала heartbeat. Если этого не произошло, смотрите логи региона: события
`region_heartbeat_disabled` (не хватает переменных) и `region_heartbeat_failed`
(директор недоступен или токен не совпал) называют причину прямо.

## Настройка клиента

В `online-config.js` укажите адрес директора:

```js
directorUrl: "https://play-director.example.com",
url: "wss://eu.play.example.com",
```

`url` остаётся запасным вариантом: он используется, если директор недоступен или
не отдал ни одного пригодного региона. Для Android-сборки заполнить нужно оба
поля — файловому клиенту неоткуда взять same-origin адрес.

После изменения повторите синхронизацию и сборку:

```powershell
npm run sync:android
npm run build:apk
```

## Обслуживание

Директор не хранит состояние матчей, поэтому его можно перезапускать в любой
момент: идущие матчи не прерываются, а регионы перерегистрируются со следующим
heartbeat. Обновление:

```bash
git pull --ff-only
docker compose --env-file .env -f deploy/compose.director.yml build --pull
docker compose --env-file .env -f deploy/compose.director.yml up -d --remove-orphans
```

Вывести регион из ротации без остановки идущих на нём матчей нельзя одним
переключателем: остановите приём новых игроков на самом регионе (например,
уменьшив `MAX_MATCHES` и дождавшись опустошения), после чего heartbeat перестанет
объявлять его пригодным.

Ротация `DIRECTOR_TOKEN` требует одновременного обновления директора и всех
регионов: до этого их heartbeat будет отвергаться с `401`, и регионы исчезнут из
списка через `REGION_TTL_MS`.

## Локальная проверка без доменов

```bash
DIRECTOR_TOKEN=local-token npm run director:start
```

и в другом окне игровой сервер:

```bash
REGION_ID=local REGION_PUBLIC_URL=ws://127.0.0.1:8787/online \
  DIRECTOR_URL=http://127.0.0.1:8686 DIRECTOR_TOKEN=local-token npm run server:start
```

Автоматическая проверка этой же связки — в
`server/test/region-heartbeat.test.js` и `server/director/test/`.
