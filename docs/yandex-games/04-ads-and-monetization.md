## 1. Обязательные правила рекламы

- Любая реклама внутри игры вызывается только через SDK Яндекс Игр.
- Сторонние блоки, статичные рекламные изображения и рекламный текст запрещены.
- Нельзя изменять платформенный блок или имитировать собственный interstitial/rewarded-блок.
- Дополнительный постоянный формат — только стики-баннер; кастомные RTB-блоки запрещены.
- После перехода по объявлению и возврата состояние игры сохранено.
- Ориентация рекламы соответствует ориентации игры.
- Interstitial и rewarded video останавливают игровой процесс и весь звук.
- Реклама появляется в логической паузе и не провоцирует случайный клик.
- Если пользователь купил отключение рекламы, все управляемые игрой форматы — interstitial, rewarded и стики — больше не показываются; поведение автоматической стартовой рекламы нужно заранее подтвердить у платформы.
- Rewarded video является добровольной; награда не может быть условием доступа к основному геймплею.
- Игра должна корректно продолжаться, даже если рекламы нет, вызов отклонён по частоте или произошла ошибка.

Случайные клики считаются признаком рекламного фрода и снижают доход. Не показывайте блок поверх активного ввода.

## 2. Автоматическая реклама на старте

Платформа автоматически показывает полноэкранную рекламу при запуске игр. У неё нет callback-функций вашей игры.

Рекомендуемый способ — подписаться сразу после инициализации:

```js
const ysdk = await YaGames.init();

ysdk.on('game_api_pause', () => {
  setPlatformPaused(true);
  pauseGameLoop();
  pauseAllGameAudio();
});

ysdk.on('game_api_resume', () => {
  setPlatformPaused(false);
  resumeGameIfNoOtherPause();
  restoreAudioIfUserDidNotMute();
});
```

Эти же события приходят при:

- вызванной игрой полноэкранной рекламе;
- rewarded video;
- окне покупки;
- смене вкладки;
- сворачивании браузера.

Пауза должна быть многоисточниковой: платформенный `resume` не снимает пользовательскую паузу, не закрывает меню и не включает отключённый пользователем звук.

## 3. Где допустима полноэкранная реклама

### Сводная таблица

| Ситуация | Допустимый момент | Дополнительное условие |
|---|---|---|
| Меню, выбор уровня, «Следующий», «Повторить», «Магазин» | Сразу после неигрового действия | Начало показа не позднее 0,33 секунды после реакции кнопки |
| Условно-пошаговая игра: викторина, пазл, merge | Сразу после завершённого игрового действия | Не позднее 0,33 секунды; отдельное предупреждение не требуется |
| Real-time, уровень короче 5 минут | Внутри уровня нельзя | Можно между уровнями или после неигрового действия |
| Real-time, уровень длиннее 5 минут | По таймеру внутри уровня | Заметное предупреждение 2 секунды; управление и геймплей уже стоят на паузе |
| Модальное окно, открытое игроком и блокирующее геймплей | После действия открытия | По правилам неигрового действия |
| Немодальное окно, под которым игра продолжается | По правилам активного геймплея | Для real-time зависит от длительности уровня |

### Лимит 0,33 секунды

Для показа после действия промежуток между визуальной реакцией элемента на нажатие и началом рекламы — не более 330 мс.

Проверка видеозаписью:

| Частота записи | Максимум кадров |
|---:|---:|
| 24 FPS | 8 |
| 30 FPS | 10 |
| 60 FPS | 20 |

Проверьте обычный сеанс, инкогнито и другое устройство. Если задержка стабильно превышает лимит, интеграция не соответствует правилу.

### Длинный real-time уровень

Предупреждение:

- заметное и читаемое;
- длится 2 секунды;
- показывается один раз перед блоком;
- во время него уже нельзя управлять игрой или совершать игровые действия;
- декоративная анимация может продолжаться.

Не используйте безусловный таймер:

```js
// Неправильно: игнорирует состояние геймплея и действия игрока.
setInterval(() => ysdk.adv.showFullscreenAdv(), 180000);
```

Частоту interstitial регулирует платформа. При слишком частом запросе блок не откроется, а консоль браузера может показать предупреждение.

## 4. Полноэкранный блок

```js
ysdk.adv.showFullscreenAdv({
  callbacks: {
    onOpen: () => {
      console.log('Реклама открыта');
    },
    onClose: (wasShown) => {
      console.log(
        wasShown ? 'Блок был показан' : 'Фактического показа не было'
      );
      continueGameFlow();
    },
    onError: (error) => {
      console.error('Ошибка рекламы', error);
    }
  }
});
```

Callbacks:

- `onOpen()` — блок успешно открылся;
- `onClose(wasShown)` — блок закрыт либо запрос закончился без показа; `wasShown` сообщает, был ли фактический показ;
- `onError(error)` — объект ошибки.

Статья не обещает стабильный набор полей у `error`, поэтому не стройте критическую логику на предполагаемом `error.code`.

### Одноразовое завершение потока

`onError` и завершающий `onClose` могут относиться к одному запросу. Защитите продолжение уровня:

```js
function showInterstitial(afterAd) {
  let finished = false;

  const finishOnce = (wasShown) => {
    if (finished) return;
    finished = true;
    afterAd?.(wasShown);
  };

  ysdk.adv.showFullscreenAdv({
    callbacks: {
      onClose: (wasShown) => finishOnce(wasShown),
      onError: (error) => {
        console.error(error);
        finishOnce(false);
      }
    }
  });
}
```

Не делайте показ обязательным условием перехода на следующий уровень: `onClose(false)` и ошибка должны вести в рабочее продолжение.

## 5. Rewarded video

Требования к кнопке:

- игрок сам нажимает её;
- текст прямо сообщает, что будет реклама;
- заранее названа точная награда;
- награда — дополнительный бонус;
- без рекламы можно продолжить основную игру.

Корректные подписи:

```text
Посмотреть рекламу → получить 50 монет
Реклама → дополнительная попытка
```

Некорректные:

```text
Продолжить
Забрать
Следующий уровень
```

API:

```js
const rewardClaimId = crypto.randomUUID();

ysdk.adv.showRewardedVideo({
  callbacks: {
    onOpen: () => {
      console.log('Rewarded video открыто');
    },
    onRewarded: () => {
      // Единственный официальный сигнал заслуженной награды.
      void enqueueRewardForReliableDelivery({
        id: rewardClaimId,
        kind: 'coins',
        amount: 50
      });
    },
    onClose: () => {
      closeRewardDialog();
    },
    onError: (error) => {
      console.error('Rewarded video недоступно', error);
      showAdUnavailableMessage();
    }
  }
});
```

Главное правило: награду выдаёт только `onRewarded`. `onClose`, `wasShown` или сам факт открытия не подтверждают полный просмотр.

Награду нужно доставлять надёжно, а не просто попытаться начислить один раз:

1. Создайте уникальный ID попытки до показа.
2. В `onRewarded` положите требование на награду в устойчивую очередь — например, IndexedDB или серверную базу.
3. Начисляйте по этому ID идемпотентно: повторная доставка не должна удваивать награду.
4. Удаляйте запись из очереди только после успешного начисления и сохранения.
5. Повторяйте незавершённые доставки после восстановления сети и при следующем запуске игры.

Защитите обработчик от повторного callback и обрабатывайте закрытие окна независимо. Документация описывает callbacks по отдельности и не обещает их относительный порядок, поэтому `onClose` не должен объявлять, что награды точно не было. Ниже `rewardOutbox` — устойчивое хранилище с методами `putIfAbsent`, `listPending` и `markDelivered`; `grantAndSaveExactlyOnce` атомарно проверяет ID, начисляет награду и сохраняет этот ID как обработанный:

```js
async function retryPendingRewards() {
  for (const claim of await rewardOutbox.listPending()) {
    try {
      await grantAndSaveExactlyOnce(claim);
      await rewardOutbox.markDelivered(claim.id);
    } catch (error) {
      // Запись остаётся pending: повторим после восстановления сети
      // или при следующем запуске игры.
      console.error('Доставка награды будет повторена', error);
    }
  }
}

async function enqueueRewardForReliableDelivery(claim) {
  try {
    await rewardOutbox.putIfAbsent(claim);
    await retryPendingRewards();
  } catch (error) {
    // Не считаем операцию завершённой. Храним claim в памяти
    // и повторяем запись, пока она не попадёт в устойчивую очередь.
    scheduleRewardEnqueueRetry(claim);
    console.error('Награда поставлена на повторную доставку', error);
  }
}

function showRewarded(reward, refreshRewardUi) {
  const claim = {
    id: crypto.randomUUID(),
    ...reward
  };
  let rewardStarted = false;

  ysdk.adv.showRewardedVideo({
    callbacks: {
      onRewarded: () => {
        if (rewardStarted) return;
        rewardStarted = true;
        void enqueueRewardForReliableDelivery(claim);
      },
      onClose: () => {
        closeRewardDialog();
        refreshRewardUi?.();

        // Не делаем вывод «награды нет»: onRewarded обрабатывается
        // самостоятельно, независимо от момента закрытия окна.
      },
      onError: (error) => {
        console.error(error);
        closeRewardDialog();
      }
    }
  });
}
```

Частота запроса rewarded video SDK формально не ограничена, но каждый показ остаётся добровольным и понятным пользователю.

`scheduleRewardEnqueueRetry` в примере — часть логики игры: она должна повторять сохранение с задержкой и не отбрасывать `claim`. При серверной экономике лучше отправлять ID на сервер, где начисление и запись обработанного ID выполняются в одной транзакции.

## 6. Стики-баннер

Настройка на вкладке **Реклама**:

- мобильный portrait — сверху или снизу;
- мобильный landscape — сверху, снизу или справа;
- десктоп — справа.

По умолчанию баннер появляется на старте и остаётся всю сессию. Для ручного управления включите **Использовать API для показа sticky-баннера**. Для игры, продающей отключение рекламы, эта опция обязательна: иначе код не сможет гарантированно скрыть уже настроенный стики-баннер.

```js
const status = await ysdk.adv.getBannerAdvStatus();

if (status.stickyAdvIsShowing) {
  console.log('Баннер уже показывается');
} else if (status.reason) {
  console.warn('Баннер недоступен', status.reason);
} else {
  const result = await ysdk.adv.showBannerAdv();
  console.log(result.stickyAdvIsShowing, result.reason);
}

// При открытии экрана, где баннер мешает, или после покупки no-ads:
await ysdk.adv.hideBannerAdv();
```

Методы:

- `getBannerAdvStatus()` — получить статус;
- `showBannerAdv()` — показать;
- `hideBannerAdv()` — скрыть.

Документированные причины:

- `ADV_IS_NOT_CONNECTED` — формат не подключён;
- `UNKNOWN` — ошибка на стороне Яндекса.

Учтите баннер при расчёте безопасной области интерфейса. Он не должен перекрывать управление, текст или важную информацию.

## 7. Тестирование рекламы

- Проверить автоматическую стартовую рекламу до запуска звука и цикла.
- Проверить `game_api_pause`/`game_api_resume` через debug-панель.
- Проверить interstitial в каждой точке вызова.
- Проверить возврат после перехода по объявлению: уровень, позиция, счёт и UI не потеряны.
- Проверить `onClose(false)` и `onError`: игра не зависает.
- Закрытие rewarded до `onRewarded` не даёт награду.
- `onRewarded` даёт награду ровно один раз и сразу сохраняет её.
- Проверить портретную/альбомную мобильную версию и десктоп со стики-баннером.
- Проверить купленное отключение рекламы в текущем и новом сеансе.
- Проверить отсутствие сети: реклама не показывается, а игра остаётся работоспособной.
- Проверить лимит 0,33 секунды и двухсекундное предупреждение там, где они нужны.
- Убедиться, что DevTools не содержит влияющих на работу ошибок.

При локальном запуске реклама может не появляться из-за ограничений хостинга. Финальная проверка выполняется в режиме черновика на реальном адресе платформы. В офлайн-режиме блоки не показываются, показы и клики не учитываются.

## 8. Подключение денежных выплат: две схемы

### Сначала проверьте профиль

В Консоли откройте **Профиль → Единая лицензионная схема**.

| Значение | Действия |
|---|---|
| **Подключена** | Использовать единое соглашение и реквизиты Консоли. Отдельный договор РСЯ не нужен. |
| **Не подключена** | Подключить прежнюю схему через РСЯ и следить за уведомлением о переводе. |

### Единая лицензионная схема

Она объединяет:

- внутреннюю рекламу Яндекса;
- стороннюю рекламу;
- инап-покупки.

Особенности на дату сбора:

- документы, реквизиты и финансовая статистика находятся в Консоли;
- доход от рекламы и покупок приходит одним платежом;
- выплата не чаще одного раза в месяц;
- минимальный порог — 3000 рублей;
- после достижения порога выплата выполняется в течение 20 рабочих дней следующего месяца;
- недостигнутая сумма переносится на следующие месяцы;
- доход суммируется по всем играм и видам монетизации;
- денежные метрики доступны владельцу и участникам с ролью **Просмотр дохода**.

Условия, налоговый статус и ставки являются финансово-правовой информацией и могут меняться. Перед указанием реквизитов проверьте актуальное лицензионное соглашение в Консоли.

### Прежняя схема через РСЯ

1. Создать аккаунт РСЯ на том же логине Яндекса, что и аккаунт Яндекс Игр.
2. Принять условия, указать актуальные контакты и реквизиты.
3. Дождаться акцепта оферты.
4. Встроить SDK и загрузить архив.
5. На вкладке **Реклама** нажать **Подключить монетизацию**.
6. Настроить стики-баннеры.
7. Проверить рекламу в черновике и пройти модерацию.

Блоки для игры создаются автоматически после публикации при успешной регистрации в РСЯ. Вызовы SDK не требуют ручного `partnerID` или ID рекламного блока.

Внутренняя монетизация работает на доменах:

```text
yandex.ru
yandex.kz
yandex.uz
yandex.by
```

Внешняя монетизация через подключённые сети работает на `yandex.com`.

На официальной странице для внешней монетизации указаны пороги 3000 рублей или 150 долларов в зависимости от договора и выплата в течение 20 рабочих дней следующего месяца. Условия внутренней выплаты зависят от страны и юридического статуса и проверяются в интерфейсе РСЯ.

## 9. Видимый показ и статистика

В старом потоке РСЯ показ считается видимым, если:

- не менее 50% площади блока находится в видимой области;
- это продолжается минимум 2 секунды.

Ошибочные и недобросовестные клики фильтруются.

Реальная статистика появляется после публикации и создания рабочих блоков:

- в Консоли: **Метрики → Метрики монетизации → Доход**;
- в РСЯ: фильтры **Сайт / приложение** и **Название блока** (`fullscreen`, `rewarded`).

Не используйте в РСЯ фильтр **Тип блока** для разделения форматов: блоки Яндекс Игр могут отображаться там как тип «Баннер».

## 10. Подключение монетизации без собственных рекламных вызовов

Нужно разделять два понятия:

- пункт 1.12 требует подключить доступную схему рекламной монетизации;
- собственные вызовы interstitial/rewarded через SDK являются необязательной, хотя и рекомендуемой возможностью.

Если игра не вызывает рекламные блоки сама:

1. Всё равно интегрируйте обязательный SDK.
2. Подключите доступную аккаунту схему монетизации.
3. В комментарии разработчика прямо укажите, что developer-initiated вызовы рекламы не используются.
4. Учтите автоматическую стартовую рекламу платформы и корректно останавливайте звук/геймплей; обработка событий `game_api_pause`/`game_api_resume` формально опциональна, но является рекомендуемым способом.

## 11. Инап-покупки

### Платформенные требования

- Платежи — только через SDK Яндекс Игр.
- На ТВ покупки запрещены.
- Стоимость показана цифрами и с портальной валютой.
- Название и иконка валюты получены из SDK.
- Пользователь получает ровно тот товар, который показан в предложении.
- Список в игре совпадает с активными товарами Консоли.
- Купленные ценности и прогресс доступны на разных устройствах.
- Необработанные платежи восстанавливаются.
- Расходуемые покупки консумируются только после надёжного начисления.

### Подключение

1. Проверить единую лицензионную схему.
2. Если она подключена, покупки доступны через единое соглашение.
3. Если нет — подключить РСЯ, дождаться акцепта и следовать инструкции Консоли; старая схема требует обращения на `games-partners@yandex-team.ru` с названием и ID игры.
4. Добавить товары.
5. Реализовать каталог, покупку, восстановление и консумирование.
6. Добавить тестовый логин и проверить без реального списания.
7. Отправить обновлённый архив на модерацию.

Ограничения товара:

- до 500 товаров в игре;
- цена — целое число в портальной валюте;
- иконка — PNG 256 × 256;
- название и описание — на русском и английском;
- описание — до 200 символов;
- CSV-импорт — до 100 товаров за один раз.

### Каталог

```js
const payments = await ysdk.getPayments();
const catalog = await payments.getCatalog();
```

Используйте значения товара из SDK:

- `title`;
- `description`;
- `imageURI`;
- `price`, `priceValue`, `priceCurrencyCode`;
- `getPriceCurrencyImage(size)`.

Не зашивайте название и значок портальной валюты вручную.

### Расходуемая покупка

Следующие клиентские примеры предполагают режим `signed: false` (значение по умолчанию), в котором `purchase()` возвращает открытые поля покупки, а `getPurchases()` — массив. При `signed: true` эти данные находятся внутри `signature` и должны разбираться только доверенным сервером.

```js
const purchase = await payments.purchase({
  id: 'gold500',
  developerPayload: JSON.stringify({
    source: 'starter-offer'
  })
});

// Сначала начислить и сохранить ценность.
await player.incrementStats({ gold: 500 });

// Затем удалить обработанную запись.
await payments.consumePurchase(purchase.purchaseToken);
```

После `consumePurchase()` запись исчезает без возможности восстановления. Поэтому порядок «consume → начисление» недопустим.

### Постоянная покупка

Например, отключение рекламы:

```js
const purchases = await payments.getPurchases();

const adsDisabled = purchases.some(
  (item) => item.productID === 'disable_ads'
);

if (adsDisabled) {
  disableInterstitialCalls();
  disableRewardedCalls();
  await ysdk.adv.hideBannerAdv();
}
```

Постоянную покупку не консумируют.

Если товар обещает «отключить всю рекламу», после покупки не должны появляться interstitial, rewarded video и стики-баннер. Для скрытия стики заранее включите в Консоли управление через API. У автоматической стартовой рекламы нет документированного игрового API отключения, поэтому до продажи blanket no-ads подтвердите в поддержке, как платформа будет подавлять стартовый показ для владельца товара; иначе не обещайте пользователю недостижимое полное отсутствие рекламы.

### Восстановление незавершённых покупок

Проверка необработанных покупок обязательна; запуск игры — рекомендуемый момент. В клиентском режиме переберите открытый массив, идемпотентно начислите незавершённые расходуемые товары и консумируйте только их:

```js
async function recoverPendingPurchases() {
  const purchases = await payments.getPurchases();

  for (const purchase of purchases) {
    if (purchase.productID === 'gold500') {
      if (!await wasPurchaseTokenProcessed(purchase.purchaseToken)) {
        await player.incrementStats({ gold: 500 });
        await rememberProcessedToken(purchase.purchaseToken);
      }

      await payments.consumePurchase(purchase.purchaseToken);
    }
  }
}
```

Сбой между начислением и консумированием не должен позволить повторно начислить тот же токен. Самая надёжная схема — серверная база обработанных `purchaseToken`.

В режиме `signed: true` `getPurchases()` не возвращает клиенту массив: он возвращает `signature`. Отправьте подпись серверу, проверьте и разберите её там, а затем верните клиенту подтверждённые токены расходуемых товаров для `consumePurchase()`.

### Серверная защита

```js
const ysdk = await YaGames.init({ signed: true });
const payments = await ysdk.getPayments({ signed: true });

const result = await payments.purchase({
  id: 'gold500',
  developerPayload: 'offer-42'
});

const response = await fetch('https://game.example/purchase', {
  method: 'POST',
  headers: { 'Content-Type': 'text/plain' },
  body: result.signature
});

if (!response.ok) {
  throw new Error('Сервер не подтвердил начисление');
}

const { granted, purchaseToken } = await response.json();

if (!granted || !purchaseToken) {
  throw new Error('Некорректный ответ сервера');
}

// Только после подтверждённого серверного начисления.
await payments.consumePurchase(purchaseToken);
```

Сервер:

1. проверяет подпись секретным ключом игры;
2. проверяет, что токен не использован;
3. начисляет ценность;
4. сохраняет токен как обработанный.
5. возвращает клиенту подтверждение и `purchaseToken`; клиент консумирует расходуемую покупку.

Секретный ключ хранится только на сервере.

Если ответ сервера потерян после начисления, при следующей обязательной проверке `getPurchases()` сервер должен распознать уже обработанный токен и вернуть тот же успешный результат с `purchaseToken`, не начисляя товар повторно. Тогда клиент сможет завершить `consumePurchase()`.

### Тестирование покупок

- Добавить Яндекс-логин в **Инап-покупки → Настройки → Список логинов для тестовых покупок**.
- Подождать применения настройки.
- Запустить черновик или prod-окружение под этим логином.
- Проверить успех, отмену, нехватку средств/ошибку, таймаут, потерю сети и повторный запуск.
- Убедиться, что деньги не списываются, а тестовая покупка проходит полный кодовый поток.
- Проверить восстановление незавершённой покупки до отправки на модерацию.
