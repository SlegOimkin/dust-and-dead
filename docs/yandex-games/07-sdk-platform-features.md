## 1. Ярлык на рабочий стол

SDK может открыть нативный диалог, через который пользователь добавляет ярлык. Возможность опциональна и зависит от:

- устройства;
- правил текущего браузера;
- внутренних ограничений Яндекс Игр.

Нельзя считать функцию доступной для всех пользователей.

### 1.1. Проверка доступности

Перед показом собственной кнопки вызовите:

```js
const ysdk = await YaGames.init();
const promptState = await ysdk.shortcut.canShowPrompt();

if (promptState.canShow) {
  showAddShortcutButton();
} else {
  hideAddShortcutButton();
}
```

Схематическое представление результата по примеру страницы:

```ts
{
  canShow: boolean;
}
```

- `true` — предложение сейчас можно показать;
- ложное значение — кнопку или другое предложение показывать не следует.

Это не опубликованный TypeScript-интерфейс: страница показывает обращение к полю `canShow`, но не задаёт формальную сигнатуру результата. Она также не определяет причины недоступности, список поддерживаемых браузеров или событие изменения `canShow`. Поэтому проверяйте возможность непосредственно перед тем, как предложить действие.

### 1.2. Открытие диалога

Диалог следует открывать после осознанного действия игрока:

```js
async function requestShortcut() {
  const availability = await ysdk.shortcut.canShowPrompt();
  if (!availability.canShow) return;

  const result = await ysdk.shortcut.showPrompt();

  if (result.outcome === 'accepted') {
    await grantOptionalShortcutReward();
  }
}
```

Страница документирует только успешное значение:

```js
result.outcome === 'accepted'
```

Начислять награду разрешено, но не обязательно. Другие возможные строки `outcome`, коды ошибок, лимиты частоты и гарантии повторного показа на странице не перечислены. Не привязывайте игровую логику к придуманным значениям вроде `rejected` или `dismissed`.

`showAddShortcutButton()`, `hideAddShortcutButton()` и `grantOptionalShortcutReward()` в примерах — условные функции игры, а не методы SDK.

### 1.3. Особенность первого ярлыка

Поведение зависит от уже существующих ярлыков:

1. Если ярлыка каталога Яндекс Игр ещё нет, первый вызов создаёт ярлык каталога.
2. Если ярлык каталога уже существует, создаётся ярлык с прямой ссылкой на игру.

Поэтому первый вызов `showPrompt()` не гарантирует появление отдельного ярлыка именно этой игры. Страница не уточняет, как отказ пользователя при первом вызове влияет на следующий вызов.

### 1.4. Полная последовательность

```text
Инициализировать SDK
→ вызвать canShowPrompt()
→ показать кнопку только при canShow
→ дождаться действия игрока
→ вызвать showPrompt()
→ реагировать только на документированное outcome === "accepted"
```

Проверьте сценарии недоступности, принятия предложения и повторного посещения игры.

## 2. Переменные окружения

После `YaGames.init()` объект `ysdk.environment` содержит сведения о текущем запуске.

### 2.1. Полная структура

```ts
interface Environment {
  app: {
    id: string;
  };
  i18n: {
    lang: string;
  };
  payload?: string;
  referrer?: {
    type: 'promo';
    promoId: string;
    intent?: string;
    inappId?: string;
  };
}
```

| Поле | Тип | Наличие | Назначение |
|---|---|---|---|
| `app` | `object` | Всегда | Данные текущей игры |
| `app.id` | `string` | Всегда | ID игры |
| `i18n` | `object` | Всегда | Параметры локализации платформы |
| `i18n.lang` | `string` | Всегда | Язык интерфейса Яндекс Игр в ISO 639-1 |
| `payload` | `string` | Опционально | Значение query-параметра `payload` |
| `referrer` | `object` | Опционально | Данные перехода из промоакции |
| `referrer.type` | `"promo"` | Внутри `referrer` | Тип рекламного перехода |
| `referrer.promoId` | `string` | Внутри `referrer` | ID промоакции из Консоли |
| `referrer.intent` | `string` | Опционально | Внутренняя команда маршрутизации |
| `referrer.inappId` | `string` | Опционально | ID инап-покупки скидочной акции |

### 2.2. ID игры

```js
const currentGameId = ysdk.environment.app.id;
```

Поле имеет тип `string`. Оно позволяет определить текущую игру без жёстко заданного ID в коде.

### 2.3. Автоматический выбор языка

```js
const portalLanguage = ysdk.environment.i18n.lang;
selectInitialLocale(portalLanguage);
```

Значение соответствует языку интерфейса Яндекс Игр и имеет формат ISO 639-1, например:

```text
ru
en
tr
```

Этот параметр необходимо использовать для стартового автоопределения языка согласно пункту 2.14 требований. Собственный переключатель языка разрешён, но не заменяет автоматический выбор при запуске.

### 2.4. Произвольный `payload`

Параметр можно передать в URL:

```text
https://yandex.ru/games/app/123?payload=test
```

Получение:

```js
const launchPayload = ysdk.environment.payload;
```

В примере результатом будет строка `"test"`. Поле отсутствует при запуске без `payload`.

Официальная страница не задаёт формат содержимого, правила валидации или прикладную семантику этой строки. Игра определяет их самостоятельно.

## 3. Переходы из промоакций

`environment.referrer` появляется, когда игрок открывает игру через акционный баннер. При обычном запуске значение равно `undefined`.

### 3.1. Настройка

1. Создайте промоакцию в Консоли разработчика.
2. Платформа сформирует диплинк для акционного баннера.
3. После инициализации SDK прочитайте `ysdk.environment.referrer`.
4. Откройте подходящий экран: оффер, магазин или связанную покупку.
5. При необходимости подключите Яндекс Метрику для аналитики переходов и конверсий.
6. Проверьте переход из интерфейса Консоли.

Формат ссылки:

```text
https://yandex.ru/games/app/{id}?lang=ru&referrer=promo&promo_id={PROMO_ID}&promo_intent={INTENT}&inapp_id={INAPP_ID}
```

`lang=ru` в примере является отдельным параметром URL и не входит в объект `referrer`.

### 3.2. Сопоставление URL и SDK

| Query-параметр | Поле SDK | Назначение |
|---|---|---|
| `referrer=promo` | `referrer.type === "promo"` | Помечает переход из акции |
| `promo_id` | `referrer.promoId` | ID акции |
| `promo_intent` | `referrer.intent` | Команда внутренней маршрутизации |
| `inapp_id` | `referrer.inappId` | ID связанной инап-покупки |

`type` и `promoId` присутствуют внутри полученного `referrer`. `intent` и `inappId` опциональны. `inappId` используется только для скидочных акций.

### 3.3. Обработка перехода

```js
const { referrer } = ysdk.environment;

if (referrer?.type === 'promo') {
  trackPromoOpen(referrer.promoId);

  if (referrer.inappId) {
    showPurchaseScreen(referrer.inappId);
  } else if (referrer.intent) {
    openScreen(referrer.intent);
  } else {
    showDefaultPromoScreen(referrer.promoId);
  }
}
```

Приоритет в официальном примере:

1. `inappId`;
2. затем `intent`.

Безопасный базовый экран по `promoId` — практическое дополнение этого руководства для акции без двух опциональных полей, а не отдельный шаг официального примера.

`showPurchaseScreen()`, `openScreen()` и аналитические функции в примере реализует сама игра — это не методы SDK. Наличие `inappId` не начисляет товар: оно лишь помогает открыть штатный сценарий покупки.

### 3.4. Проверка

На вкладке **Промоакции** используйте поле **Проверить переход**:

- **В опубликованной версии**;
- **В черновике**.

Игра должна открыть ожидаемый оффер, магазин или конкретную инап-покупку. Проверяйте неизвестный `intent`, отсутствующий товар и акцию без `intent`/`inappId`, чтобы переход не приводил к пустому экрану.

### 3.5. Типовые сценарии

| Сценарий | Аудитория | Цель | Пример маршрутизации |
|---|---|---|---|
| Скидка на товар | Неплатящие игроки | Первый платёж | `SPRING_DISCOUNT` + `open_starter_pack` + `starter_pack_001` → экран покупки |
| VIP-оффер | Платящие игроки | Рост среднего чека | `VIP_PROMO` + `open_shop` → магазин |
| Сезонная акция | Все активные игроки | Удержание | `SALE_SPRING_2026` → общий акционный экран или баннер |

Сам `referrer` не собирает полную аналитику конверсий. Для неё документация отдельно предлагает подключить Яндекс Метрику.

## 4. Серверное время

```js
const timestamp = ysdk.serverTime();
```

Метод:

```ts
serverTime(): number;
```

Он возвращает синхронизированную временную метку в миллисекундах:

- формат совместим с результатом `Date.now()`;
- системные часы устройства на значение не влияют;
- время согласовано между устройствами;
- вызов выполняется после инициализации SDK;
- при каждой проверке нужно получать свежее значение.

Подходящие задачи:

- ежедневные и еженедельные бонусы;
- сезоны и ограниченные события;
- временные квесты;
- защита игровых таймеров от перевода часов устройства.

`serverTime()` предоставляет доверенный источник времени, но сам по себе не защищает сохранения, начисления или серверную экономику от подмены и гонок.

### 4.1. Награда через каждые 24 часа

Следующие фрагменты предполагают, что `ysdk` уже получен через `await YaGames.init()`. Для 24-часовой модели храните timestamp последней выдачи:

```js
const player = await ysdk.getPlayer();
const saved = await player.getData();
const now = ysdk.serverTime();
const previous = saved.lastRewardTime ?? 0;
const dayInMilliseconds = 24 * 60 * 60 * 1000;

if (now - previous >= dayInMilliseconds) {
  await giveReward();
  await player.setData({
    lastRewardTime: now
  });
}
```

Поведение:

- при отсутствии сохранённой метки награда доступна сразу;
- новая выдача разрешается после 86 400 000 мс;
- часовой пояс и локальное время суток не учитываются;
- фактически интервал считается после последнего получения награды, а не после любого посещения.

`giveReward()` — функция игры. В официальной схеме сначала начисляется награда, затем сохраняется timestamp. При ошибке сохранения возможна повторная выдача. Для ценной экономики используйте идемпотентный ID операции или серверную транзакцию.

### 4.2. Награда один раз в календарные сутки UTC

Храните строку UTC-даты:

```js
const player = await ysdk.getPlayer();
const saved = await player.getData();
const now = ysdk.serverTime();
const currentUtcDay = new Date(now).toISOString().split('T')[0];
const previousUtcDay = saved.lastRewardDate ?? '';

if (currentUtcDay !== previousUtcDay) {
  await giveReward();
  await player.setData({
    lastRewardDate: currentUtcDay
  });
}
```

Поведение:

- дата имеет формат `YYYY-MM-DD`;
- первая награда доступна сразу;
- общий сброс происходит в `00:00 UTC`;
- между выдачами может пройти меньше 24 часов, если первая получена перед полуночью UTC;
- локальная полночь пользователя не учитывается.

`toISOString()` использует UTC. Этот вариант не подходит для сброса по местному часовому поясу игрока.

### 4.3. Разница двух моделей

| Модель | Хранимое значение | Момент новой выдачи |
|---|---|---|
| Интервал 24 часа | Timestamp последней награды | После полных 86 400 000 мс |
| Календарные сутки | Строка `YYYY-MM-DD` | После смены даты в UTC |

Не смешивайте обе модели. В обоих вариантах предусмотрите обработку ошибок, параллельных вкладок и повторного запуска. Для ценных наград сохранение факта выдачи и начисление должны быть идемпотентными.

## 5. События SDK

### 5.1. Пауза и возобновление

Платформа отправляет:

- `game_api_pause` — приостановить игровой цикл, музыку и звуки;
- `game_api_resume` — разрешить корректное возобновление.

Поддержка этих событий помогает выполнить пункты 1.3 и 4.7 требований модерации. Игры с такой поддержкой также могут дополнительно распространяться на внешних площадках.

События охватывают:

- полноэкранную рекламу;
- rewarded-рекламу;
- окно покупок;
- переключение вкладок;
- сворачивание и восстановление окна браузера.

Подписка и отписка:

```js
const pauseHandler = () => {
  pauseGameLoop();
  pauseAllAudio();
};

const resumeHandler = () => {
  resumeGameWithoutBreakingUserPause();
};

ysdk.on('game_api_pause', pauseHandler);
ysdk.on('game_api_resume', resumeHandler);

// При уничтожении сцены:
ysdk.off('game_api_pause', pauseHandler);
ysdk.off('game_api_resume', resumeHandler);
```

События согласованы с разметкой геймплея:

- при платформенной паузе вызывается `GameplayAPI.stop()`;
- при возобновлении вызывается `GameplayAPI.start()`;
- если до платформенной паузы игра уже вызвала `GameplayAPI.stop()`, например из-за меню, при последующем `game_api_resume` платформа не вызовет `GameplayAPI.start()`.

### 5.2. Автоматическая реклама на старте

Платформа автоматически показывает полноэкранную рекламу при запуске всех игр. У этого автоматического показа нет прямых callback-функций; callbacks `showFullscreenAdv()` относятся к рекламным блокам, которые вызывает сама игра.

Надёжная схема:

1. Сразу после инициализации подписаться на `game_api_pause` и `game_api_resume`.
2. На `pause` остановить звук и геймплей.
3. Не запускать игру во время паузы.
4. На `resume` впервые запустить или корректно продолжить сессию.

```js
let started = false;
let platformPaused = false;

function applyPlatformState() {
  if (platformPaused) {
    pauseGameLoop();
    pauseAllAudio();
    return;
  }

  if (!started) {
    started = true;
    startGame();
  } else {
    resumeGameWithoutBreakingUserPause();
  }
}

ysdk.on('game_api_pause', () => {
  platformPaused = true;
  applyPlatformState();
});

ysdk.on('game_api_resume', () => {
  platformPaused = false;
  applyPlatformState();
});

// Официальная схема также выполняет начальную проверку:
applyPlatformState();
```

### 5.3. Контракт остальных событий

Документированные имена:

```ts
enum ESdkEventName {
  EXIT = 'EXIT',
  HISTORY_BACK = 'HISTORY_BACK',
  ACCOUNT_SELECTION_DIALOG_OPENED =
    'ACCOUNT_SELECTION_DIALOG_OPENED',
  ACCOUNT_SELECTION_DIALOG_CLOSED =
    'ACCOUNT_SELECTION_DIALOG_CLOSED'
}
```

Те же значения доступны через:

```js
ysdk.EVENTS.EXIT
ysdk.EVENTS.HISTORY_BACK
ysdk.EVENTS.ACCOUNT_SELECTION_DIALOG_OPENED
ysdk.EVENTS.ACCOUNT_SELECTION_DIALOG_CLOSED
```

Контракты, показанные на странице:

```ts
ysdk.on(
  eventName: ESdkEventName,
  listener: Function
): () => void;

ysdk.dispatchEvent(
  eventName: ESdkEventName,
  detail?: object
): Promise<unknown>;
```

Страница фиксирует возвращаемый тип `() => void`, но отдельно не объясняет назначение возвращённой функции. Для `game_api_pause` и `game_api_resume` она явно показывает подписку по строковому имени и снятие подписки через `ysdk.off()`.

### 5.4. TV: `HISTORY_BACK` и `EXIT`

`HISTORY_BACK` доступно только на телевизоре.

Поток:

```text
Пользователь нажимает Back
→ игра получает HISTORY_BACK
→ игра показывает собственный диалог
→ пользователь подтверждает выход
→ игра отправляет EXIT
```

```js
ysdk.on(ysdk.EVENTS.HISTORY_BACK, () => {
  showTvExitDialog({
    onConfirm: async () => {
      try {
        await ysdk.dispatchEvent(ysdk.EVENTS.EXIT);
      } catch (error) {
        showExitError(error);
      }
    }
  });
});
```

В собственном диалоге можно предложить выход, переход к настройкам, магазину или другим внутренним экранам. `EXIT` отправляется только после подтверждения игрока.

### 5.5. Выбор гостевого или авторизованного прогресса

У пользователя могут существовать два сохранения:

- гостевое;
- привязанное к авторизованному аккаунту.

Платформа показывает диалог сравнения прогресса, включая продолжительность игры и дату последнего входа. Если игра часто синхронизирует данные или использует собственный сервер, отслеживайте:

- `ACCOUNT_SELECTION_DIALOG_OPENED`;
- `ACCOUNT_SELECTION_DIALOG_CLOSED`.

```js
ysdk.on(ysdk.EVENTS.ACCOUNT_SELECTION_DIALOG_OPENED, () => {
  stopPeriodicCloudSync();
});

ysdk.on(ysdk.EVENTS.ACCOUNT_SELECTION_DIALOG_CLOSED, async () => {
  goToMainMenu();

  const selectedPlayer = await ysdk.getPlayer();
  const selectedProgress = await selectedPlayer.getData();
  restartWithProgress(selectedProgress);
});
```

Официальная страница предлагает приостановить регулярную синхронизацию при открытии, а после закрытия выйти в меню или перезапустить игру и заново получить данные. Практически безопасная последовательность этого руководства:

1. не продолжайте работу со старым объектом прогресса;
2. выйдите в главное меню или перезапустите игру;
3. заново получите `Player`;
4. заново загрузите выбранные данные;
5. только затем возобновите синхронизацию.

`pauseGameLoop()`, `pauseAllAudio()`, `resumeGameWithoutBreakingUserPause()`, `showTvExitDialog()`, `showExitError()`, `goToMainMenu()` и остальные предметные функции в примерах реализует игра — это не методы SDK.

## 6. Ссылки на другие игры разработчика

`GamesAPI` возвращает корректные ссылки на другие ваши игры с учётом текущих:

- платформы;
- домена.

Используйте полученные URL вместо самостоятельно составленных ссылок. Так игра не предложит продукт, недоступный в данном окружении.

### 6.1. Все доступные игры

```js
try {
  const result = await ysdk.features.GamesAPI.getAllGames();

  for (const game of result.games) {
    addGameCard(game);
  }

  setDeveloperPageLink(result.developerURL);
} catch (error) {
  hideOtherGamesSection();
}
```

Формат ответа:

```ts
{
  games: IGame[];
  developerURL: string;
}
```

| Поле | Тип | Значение |
|---|---|---|
| `games` | `IGame[]` | Игры разработчика, доступные на текущей платформе и домене |
| `developerURL` | `string` | Страница разработчика |

### 6.2. Одна игра по ID

```js
try {
  const result =
    await ysdk.features.GamesAPI.getGameByID(100000);

  if (result.isAvailable && result.game) {
    showRecommendedGame(result.game);
  } else {
    hideRecommendation();
  }
} catch (error) {
  hideRecommendation();
}
```

Аргумент:

| Параметр | Тип | Значение |
|---|---|---|
| `appID` | `number` | ID игры из Консоли разработчика |

Ответ:

```ts
{
  game?: IGame;
  isAvailable: boolean;
}
```

- `isAvailable === true` — объект игры доступен;
- `isAvailable === false` — `game` равен `undefined`;
- ошибка запроса обрабатывается отдельно от штатной недоступности.

### 6.3. Интерфейс `IGame`

```ts
interface IGame {
  appID: string;
  title: string;
  url: string;
  coverURL: string;
  iconURL: string;
}
```

| Поле | Тип | Значение |
|---|---|---|
| `appID` | `string` | ID игры из Консоли |
| `title` | `string` | Название |
| `url` | `string` | Ссылка на игру |
| `coverURL` | `string` | Ссылка на обложку |
| `iconURL` | `string` | Ссылка на иконку |

Обратите внимание на типы из документации:

- `getGameByID()` принимает числовой `appID`;
- возвращённый `IGame.appID` является строкой.

На TV ссылки на другие игры запрещены общим [пунктом 1.6.3.5 требований](https://yandex.ru/dev/games/doc/ru/concepts/requirements). Это дополнительное ограничение из нормативной страницы, а не из статьи `sdk-other-games`. Даже при наличии API не выводите такой блок в TV-интерфейсе.

`addGameCard()`, `setDeveloperPageLink()`, `hideOtherGamesSection()`, `showRecommendedGame()` и `hideRecommendation()` в примерах — функции интерфейса игры, а не методы SDK.

## 7. Другие объекты и параметры

### 7.1. `screen.fullscreen`

Объект `screen.fullscreen` описывает полноэкранный режим браузера.

| Член | Тип в официальной таблице | Назначение |
|---|---|---|
| `STATUS_ON` | `string` | Константа `"on"` |
| `STATUS_OFF` | `string` | Константа `"off"` |
| `status` | `string` | Текущее состояние: `STATUS_ON` или `STATUS_OFF` |
| `request` | `Promise<void>` | Запрос перехода в полноэкранный режим |
| `exit` | `Promise<void>` | Запрос выхода из полноэкранного режима |

Если ссылка на объект уже получена из SDK, его состояние можно сопоставить с константами:

```js
if (fullscreen.status === fullscreen.STATUS_ON) {
  showExitFullscreenControl();
} else if (fullscreen.status === fullscreen.STATUS_OFF) {
  showEnterFullscreenControl();
}
```

`showExitFullscreenControl()` и `showEnterFullscreenControl()` — условные функции интерфейса игры.

Важные ограничения:

- Яндекс Игры могут открыть игру сразу в полноэкранном режиме;
- многие браузеры запрещают переключение без действия пользователя;
- в правом верхнем углу экрана Яндекс Игр уже есть кнопка полноэкранного режима;
- объект нужен прежде всего для согласования кнопок внутри самой игры.

Проверяемая страница не показывает ни путь получения объекта из инициализированного SDK, ни синтаксис запуска `request` и `exit`: она перечисляет их как члены типа `Promise<void>`, а не приводит сигнатуры с круглыми скобками. Поэтому этот комплект не выдумывает исполняемый пример `request()`/`exit()` без дополнительного подтверждения. Также страница не описывает ошибки, события смены статуса и матрицу браузеров.

### 7.2. `clipboard`

Документирована запись строки:

```js
ysdk.clipboard.writeText(text);
```

`text` — строка, которую игра передаёт в буфер обмена. API чтения из буфера на этой странице не документирован.

Страница не определяет тип результата, асинхронность, ошибки, браузерные разрешения или требования пользовательского действия. Не добавляйте неподтверждённую обработку возвращаемого значения как обязательную часть API.

### 7.3. `deviceInfo`

```js
const kind = ysdk.deviceInfo.type;
```

Документированы четыре значения:

| `type` | Устройство |
|---|---|
| `"desktop"` | Компьютер |
| `"mobile"` | Мобильное устройство |
| `"tablet"` | Планшет |
| `"tv"` | Телевизор |

Проверки:

| Метод | `true` | `false` |
|---|---|---|
| `isMobile()` | Устройство определено как мобильное | Иное устройство |
| `isDesktop()` | Используется компьютер | Иное устройство |
| `isTablet()` | Используется планшет | Иное устройство |
| `isTV()` | Игра открыта на телевизоре | Иное устройство |

Точное написание TV-проверки:

```js
ysdk.deviceInfo.isMobile();
ysdk.deviceInfo.isDesktop();
ysdk.deviceInfo.isTablet();
ysdk.deviceInfo.isTV();
```

Пример:

```js
if (ysdk.deviceInfo.isTV()) {
  enableRemoteControlUi();
} else if (
  ysdk.deviceInfo.isMobile() ||
  ysdk.deviceInfo.isTablet()
) {
  enableTouchUi();
} else {
  enableKeyboardAndMouseUi();
}
```

На этой странице для `deviceInfo` не документированы ОС, браузер, разрешение, ориентация, наличие сенсорного экрана и другие значения `type`. Используйте перечисленные данные для выбора управления и крупных вариантов UI, но не вместо адаптивной вёрстки.

## 8. Итоговый чек-лист этих функций

### Ярлык

- [ ] Кнопка появляется только после успешного `canShowPrompt()`.
- [ ] `showPrompt()` вызывается после действия игрока.
- [ ] Награда выдаётся только при `outcome === "accepted"`.
- [ ] Учтено, что первый ярлык может вести в каталог, а не прямо в игру.

### Окружение и промо

- [ ] `i18n.lang` выбирает стартовую локаль.
- [ ] `payload` считается опциональным.
- [ ] `referrer` проверяется на наличие и `type === "promo"`.
- [ ] `promo_id`, `promo_intent` и `inapp_id` сопоставлены с правильными camelCase-полями.
- [ ] Для неизвестной акции предусмотрен безопасный базовый экран.
- [ ] Переход проверен из черновика и опубликованной версии.

### Серверное время

- [ ] При каждой проверке вызывается свежее `serverTime()`.
- [ ] Выбрана одна модель: 24 часа или календарные сутки UTC.
- [ ] Состояние последней награды сохраняется.
- [ ] Начисление защищено от повторов и сбоя сохранения.

### События

- [ ] Пауза останавливает цикл и весь звук.
- [ ] Resume не снимает пользовательскую или меню-паузу.
- [ ] Автоматическая стартовая реклама не запускает геймплей раньше времени.
- [ ] Подписки снимаются при уничтожении сцены.
- [ ] TV Back показывает собственный диалог, подтверждение отправляет `EXIT`.
- [ ] После выбора аккаунта заново загружаются `Player` и прогресс.

### Другие игры и параметры

- [ ] Ссылки получаются через `GamesAPI`, а не собираются вручную.
- [ ] Обработаны ошибка запроса и `isAvailable === false`.
- [ ] На TV блок других игр скрыт.
- [ ] Fullscreen-кнопка учитывает `status` и ограничения браузера.
- [ ] Для `clipboard` используется документированный `writeText()`; API чтения не считается документированным этой страницей.
- [ ] `deviceInfo` не заменяет адаптивную вёрстку.
